# 토큰 최적화 가이드 (Claude Code)

Claude Code 세션에서 컨텍스트/토큰 사용을 효율화하기 위한 실전 지침.

## 1. 파일 읽기 최소화
- 전체 파일을 다 읽지 말고, 필요한 범위만 `offset`/`limit`으로 읽는다.
- 이미 읽고 편집한 파일은 확인 목적으로 재읽기하지 않는다 (Edit/Write가 실패하면 에러로 알려줌).
- 대용량 로그/출력은 `head`/`tail`/`grep`으로 필요한 부분만 추출한다.

## 2. 탐색은 전용 도구로
- 파일 위치·심볼 검색은 `Grep`/`Glob` 또는 `Explore` 서브에이전트를 사용한다.
- 광범위한 탐색(여러 파일에 걸친 조사)은 `Explore`나 `fork`에 위임해 원본 세션의 컨텍스트를 raw 출력으로 채우지 않는다.
- "이 결과를 다시 볼 필요가 있는가?"가 fork 위임의 기준이다.

## 3. 병렬 처리
- 서로 의존성이 없는 도구 호출(파일 읽기, 독립적인 bash 명령 등)은 한 번에 병렬로 호출한다.
- 순차 호출은 반드시 이전 결과가 다음 입력에 필요할 때만 사용한다.

## 4. 서브에이전트/포크 활용 기준
- 중간 결과(도구 출력 원문)를 보존할 필요가 없는 조사성 질문은 `fork`로 위임한다.
- 완전히 새로운 컨텍스트가 필요 없다면 매번 새 general-purpose 에이전트를 스폰하지 않는다 (같은 캐시를 공유하는 fork가 더 저렴함).
- 사용자가 명시적으로 요청하지 않는 한 서브에이전트를 남발하지 않는다.

## 5. 응답 스타일
- 불필요한 서술(내부 사고 과정 나열, 매 단계 설명)을 피하고 결과와 다음 단계 위주로 간결하게 답한다.
- 코드에는 WHY가 비자명한 경우에만 한 줄 주석을 남기고, 장황한 docstring/설명 주석을 피한다.
- 최종 요약은 1~2문장으로 제한한다.

## 6. 반복 작업 방지
- 같은 실패 명령을 sleep 루프 등으로 재시도하지 않는다 — 근본 원인을 진단한다.
- 이미 확인된 사실을 다시 도출하거나, 이미 내린 결정을 재검토하지 않는다.

## 7. 지연 로딩 도구(Deferred Tools) 사용
- `ToolSearch`로 여러 도구가 필요할 경우 개별 호출 대신 `select:A,B,C` 형태로 한 번에 배치 조회한다.
- 특히 브라우저 자동화(`mcp__claude-in-chrome__*`) 도구는 작업 시작 시 필요한 도구를 한 번에 묶어 로드한다.

## 8. 메모리/컨텍스트 관리
- 코드에서 파생 가능한 정보(구조, 규칙, 파일 경로)는 메모리에 저장하지 않는다 — 실행 시점에 다시 읽는다.
- 대화가 길어지면 자동 요약(compaction)이 이루어지므로, 이미 확립된 사실을 장문으로 재진술하지 않는다.

## 9. 프롬프트 캐싱 인지
- 세션 내 반복 요청은 캐시 TTL(기본 1시간) 내에서 재사용되므로, 불필요하게 세션을 새로 시작하거나 컨텍스트를 리셋하지 않는다.
- 캐시를 유지하기 위한 목적만으로 인위적인 웨이크업/폴링을 예약하지 않는다.

# AI PRD · 제조-시장 인과 인사이트 에이전트

> Canvas v1 — dataset_1(생산·설비·품질·시장 통합 3개년 데이터) 기반 실습 PRD.

## 1. 배경

생산 현장의 설비 이상·품질 불량과, 그 제품의 시장 성과(매출·점유율) 데이터가
서로 다른 팀·다른 파일에 흩어져 있어 "이 불량이 저 매출 하락의 원인인가"를
사람이 수작업으로 엮어보기 전까지는 알기 어렵다. product_id로 두 세계가
이미 연결되어 있는데도 그 연결을 실제로 짚어보는 절차가 없다.

## 2. 목표

- 시간: 제품 하나의 원인 분석(수작업 크로스체크) — 반나절 → 수 초
- 품질: Critical 등급 결함이 실제로 존재하는 제품은 빠짐없이 리포트에 포함
- 리스크: 근거 없는 원인 단정을 자동 발행하지 않는다 (Critical 결함 누적 시 사람 승인 필수)

**MVP 한 문장:** product_id를 넣으면 생산 이상·품질 불량·시장 성과를 엮은 통합 리포트가 나오는 에이전트

## 3. 사용자

| 역할 | 설명 |
|---|---|
| 주 사용자 | 품질/생산 기획 담당자 — 특정 제품의 이상 여부를 빠르게 확인 |
| 검토자 | 품질팀 리더 — Critical 결함 리포트의 원인 판단을 승인/반려 |
| 승인자 | 품질팀 리더 (HITL 승인 큐) |

## 4. 업무 흐름

```text
As-Is: 생산팀 로그 확인 -> 품질팀 불량 대장 확인 -> 영업팀 매출 자료 요청 -> 수작업 대조 -> 보고서 작성
To-Be:  product_id 입력 -> 통합 에이전트(MCP 조회+조인) -> [Critical 결함 누적 시] 사람 승인 -> 리포트 발행
```

## 5. AI 역할

**할 일:**
- MCP 툴로 생산/품질/시장 데이터를 조회하고 product_id 기준으로 조인
- 이상 징후(OEE 저하, 센서 anomaly, Critical 결함)를 집계
- 시장점유율 급락 구간을 상시 모니터링(HOTL)하고 알림 표시

**✕ 하면 안 되는 일:**
- Critical 결함이 임계치 이상인데 사람 승인 없이 리포트를 확정 발행
- "불량이 매출 하락의 원인이다"라고 통계적 근거 없이 인과를 단정
- CSV/xlsx 소스가 불일치하는 상태에서 검증 없이 수치를 합산

**사람이 계속 하는 일:**
- Critical 결함 누적 리포트의 최종 승인/반려
- HOTL 알림이 뜬 리전×카테고리에 대해 실제 개입 여부 판단

## 7. 출력 명세

**형식:** JSON 통합 리포트(`build_causal_report`) — product_id, 이상 실행 수, Critical 결함 수/유형, 시장점유율 추이

**근거 표시:** run_id, defect_id, sales_id 등 원본 레코드 키를 그대로 유지

**목표 예시:** `outputs/report_<product_id>.json`

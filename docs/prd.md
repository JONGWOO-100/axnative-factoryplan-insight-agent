## 1. 개요

공정 엔지니어가 웨이퍼 로트 하나의 이상을 확인하려면 FDC 센서 로그·수율 팩트·DX KPI를
각각 열어 `lot_id`로 수동 조인해야 한다. 이 시스템은 `lot_id` 하나로 그 조인을 대신하고,
관련된 공정·챔버·AI에이전트·결함 관계를 GraphRAG로 함께 제시한다.

핵심은 조회 속도가 아니라 **근거 규율**이다. 이 도구는 답에 출처를 붙이고, 근거가 없으면
"모르겠다"고 말한다. 설비 이상이 임계치를 넘으면 자동 발행을 멈추고 사람 승인을 받는다.

## 2. 문제 정의

`dataset_2`를 실제로 분석해 확인한 문제들이다. 수치는 전부 재현 가능하다.

- **문제 1 — 설비 이상과 수율 사이에 상관이 없는데도 "원인"으로 보고된다.**
  `corr(die_yield_pct, 로트당 인터록 건수) = +0.0050`. 결함 유형별 평균 다이 수율은
  None(Clean) 88.16 / Bridge Defect 88.20 / Gate Particle 88.18 / Pattern Collapse 88.39 /
  Under-etching 88.12로 **무결함 로트와 결함 로트가 같다.** 인터록 보유 로트가 오히려
  근소하게 높다(88.25 vs 88.18). 그런데도 초기 리포트는 "수율 하락 원인 분석"이라는
  틀로 결과를 제시했다. 근거 없는 인과가 승인 단계로 넘어간다.

- **문제 2 — 하나의 사건이 세 개의 근거로 보고되어 확신이 부풀려진다.**
  인터록 134건은 예외 없이 VM 오차 1.5% 초과이고, 동시에 전부 `AGT-FDC-02`에 배정된다
  (2,500행 전부에서 성립). 물리적으로는 챔버 압력 +5.93σ · 플라즈마 임피던스 +4.66σ ·
  서셉터 온도 +4.37σ가 함께 튀는 **하나의 고장 모드**이고(134건 중 132건이 세 센서 모두
  +2σ 이상), VM 오차는 그 결과다(인터록군 부호 100% 양수). 그런데 리포트가 "인터록 2건,
  VM 오차 이상 2건"을 나란히 적어 독자가 독립된 두 근거로 읽었다.

- **문제 3 — 조회 결과에 출처가 없어 재확인이 불가능하다.**
  같은 로트를 두 사람이 조회해도 어느 테이블 어느 행을 봤는지 남지 않는다.
  실제로 `AGT-FDC-02`의 책임 정의("챔버 내 플라즈마 임피던스/RF 헌팅 사전 감지")를 보면
  이 에이전트는 이상의 **대응자**인데, 배정 사실만 보면 원인처럼 읽힌다.

- **문제 4 — 데이터 커버리지 공백이 드러나지 않는다.**
  전체 1,500 로트 중 **292건(19%)은 FDC 로그가 아예 없다.** AI 에이전트 5개 중
  `AGT-VM-01`·`AGT-RTM-04`·`AGT-YDA-05` 3개는 팩트 테이블 참조가 **0건**이라, 관계 질의에
  빈 결과가 온다. 공백인지 오류인지 사용자가 구분할 수 없다.

## 3. 타겟 사용자 / 이해관계자

| 사용자 | 원하는 것 | 지금 겪는 불편 |
|---|---|---|
| **공정 엔지니어** (1차·조회) | 특정 로트에 설비 이상이 있었는지, 어느 챔버·공정인지 즉시 확인 | 세 테이블을 수동 조인. 이상 여부 판단 기준이 사람마다 다름 |
| **공정 리더** (1차·**승인권자**) | 발행 전 리포트의 근거를 검증하고 승인/반려 | 리포트에 출처가 없어 재확인 불가. 인과 주장의 근거를 따질 수 없음 |
| 품질 담당자 | 발행된 리포트의 결함 추이 | 승인 이력과 반려 사유가 구조화되지 않아 집계가 안 됨 |
| DX 운영팀 | 데이터 레이크 품질·AI 자율의사결정률 추이 | KPI가 별도 테이블에 있어 현장 이슈와 연결이 안 됨 |
| 경영진 | 요약된 판단 근거 | 상세 수치는 필요 없고, 무엇을 아직 모르는지가 궁금함 |

**1차 사용자는 공정 엔지니어(조회)와 공정 리더(승인)다.** 승인 권한이 공정 조직 안에
있으므로, 승인 화면은 품질 관점의 집계보다 **해당 로트의 근거 확인**에 최적화한다 —
이상 행 수·겹침·수율차·인과 판정 사유를 한 화면에서 보고 바로 판단할 수 있어야 한다.
품질 담당자는 발행 이후의 추이를 보는 2차 사용자로 둔다.

## 4. 핵심 시나리오

FE "대화형 분석" 탭에서 실제로 검증한 흐름이다(세션 `d855e8998b`).

### 시나리오 1: 로트 원인 조회 → 근거 없음 판정 → 자동 발행 보류

1. 엔지니어가 `LOT-2503-50790`의 이상 여부를 확인하려 한다.
2. 시스템이 오케스트레이터 → GraphRAG 리트리버 → 통합 에이전트(MCP `build_causal_report`)
   → 리포트 가드레일 → HITL 게이트 6단계를 거친다.
3. 응답: FDC 이상 **2행**(인터록과 VM 오차가 같은 2행이므로 하나의 근거), 다이 수율
   88.27%로 노드 평균 88.11% 대비 저하 없음, **인과 판정 UNKNOWN — 이상이 수율로
   이어졌다는 근거 없음.**
4. 인터록이 임계치(1건) 이상이라 자동 발행이 멈추고 승인 큐로 이동한다.
5. **공정 리더**가 큐에서 근거를 보고 승인 또는 반려한다. 이 케이스는 수율 저하가 없으므로
   **반려("원인 재확인 필요")가 타당한 판단이다.**

### 시나리오 2: 관계 질의 — 에이전트가 제어하는 챔버 확인

1. 엔지니어가 `AGT-APC-03`이 제어하는 챔버와 인터록 이력을 묻는다.
2. 시스템이 GraphRAG로 `controlled_by` 엣지를 따라 챔버를 찾고 FDC 이력을 조인한다.
3. 확인된 사실: 8개 챔버 전부가 `AGT-APC-03`·`AGT-FDC-02` 둘에만 물려 있다.
   나머지 3개 에이전트는 엣지가 없다 → **데이터에 운영 연결이 없음을 명시해야 한다.**

### 시나리오 3: 승인 대기 건 처리

1. **공정 리더**가 승인 큐를 연다(현재 실데이터 2건).
2. 각 건의 근거 — 이상 행 수, 겹침, 수율차, 인과 판정 사유 — 를 확인한다.
3. 승인하면 `outputs/report_<lot_id>.json`이 발행되고, 반려하면 사유가 함께 기록된다.

## 6. 핵심 기능 요구사항

### Must (없으면 출시 못 함)

- [x] **인과를 확정하지 않는다.** 모든 리포트가 `causal_verdict`를 싣고, 값은 항상
      `UNKNOWN`이며 사유(`no_fdc_anomaly`/`no_baseline`/`no_yield_deficit`/`coincident_only`)를
      함께 남긴다. 가드레일이 다른 값과 사유 없는 UNKNOWN을 거부한다.
- [x] **같은 근거를 중복 계수하지 않는다.** 이상 행 수(합집합)를 기준으로 보고하고,
      겹침 수를 함께 싣는다. 파생 항목은 파생임을 표시한다.
- [x] **HITL 게이트.** FDC 인터록 ≥ 1건이면 자동 발행을 멈추고 승인 큐로 보낸다.
      승인해야 `outputs/`에 발행된다.
- [x] **전 구간 트레이스.** 모든 턴이 `runs/<run_id>.jsonl`에 남는다.
- [x] **키 없이도 끝까지 동작한다.** LLM 키가 없으면 결정론적 템플릿으로 대체.
- [ ] **데이터 공백을 명시한다.** FDC 로그가 없는 로트(292건)와 엣지가 없는 에이전트(3개)에
      대해 빈 결과 대신 "데이터에 해당 기록 없음"을 사유와 함께 반환한다.
- [ ] **출처를 네 요소로 표기한다.** 테이블명 · 행 식별자 · 조회 시각 · 적용한 임계치.

### Should (있으면 확실히 낫다)

- [ ] **인과 판정 기준선 교정.** 현재 비교 기준이 3개년 평균이라 시간 추세를 통제하지 못해
      `coincident_only` 판정이 생산 시점의 대리 지표가 되어 있다(2023년 87.5% vs 2026년 6.7%,
      `corr(생산일, 수율차) = +0.701`). 동일 노드 × 동일 분기 평균으로 바꾼다. → decisions.md D-007
- [ ] **라우팅 정확도 개선.** FE 기본 예상 질문 중 `AGT-APC-03 …제어하는 챔버` 가 관계
      질의인데 키워드 점수(fdc 2 : graph 1)로 FDC 에이전트에 배정된다.
- [ ] **질의 파라미터 반영.** LLM 키가 없을 때 템플릿이 질문의 대상 컬럼·기간을 무시한다

- [ ] 반려 사유의 구조화(자유 텍스트 → 사유 코드 + 메모).

## 8. 리스크 및 오픈 이슈

- **기준선 데이터가 시나리오를 지지하지 않는다** — 이 제품의 원래 시나리오는 "FDC 이상이
  수율 하락 원인"인데 데이터에 그 관계가 없다(§2 문제 1). 인과 확정 대신 근거 규율을
  제품 가치로 삼는 방향으로 정리했으나, 실제 팹 데이터에서도 같은지는 확인되지 않았다.
  → 〔가정〕 **공정 리더**가 실팹 데이터로 상관 재확인, **2026-09-30**까지.
  실데이터에서도 상관이 없다면 §1의 제품 가치 정의가 맞고, 있다면 §6 Should 첫 항목
  (기준선 교정)을 Must로 올려야 한다.
- **`coincident_only` 판정을 인과의 방증으로 오독할 위험** — 현재 기준선 때문에 사실상
  생산 연도에 따라 갈린다. §6 Should 첫 항목을 처리하기 전에는 이 판정을 근거로 쓰면 안 된다.
- **KPI에 악화 구간이 없다** — 36개월 전부 단조 개선이라 "악화 원인 분석" 기능은
  이 데이터로 검증할 수 없다.
